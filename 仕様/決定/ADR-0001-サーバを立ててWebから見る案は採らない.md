# ADR-0001 サーバを立てて Web から見られるようにする案は採らない

- **状態**：採用（棄却された道）
- **日付**：2026-08-19
- **関わる構成要素**：[配布と端末](../構成要素/配布と端末.md)
- **のちの経緯**：その後できた公開版はサーバを立てない静的配信で、書き込みを持たない（[配布と端末](../構成要素/配布と端末.md)「web を5つ目のOSとして」）

## 見送った案（2026-08-19）

（旧 SPEC.md 10章の原文）

**サーバを立てて Web から見られるようにする案は採らない。**

得られるのは「Mac を止めたまま外出先から見られる」の一点で、代わりに次を抱える。

- **認証の実装が必須。** 書き込みAPI（収集実行・ソース追加・キーワード追加・
  ブックマーク・設定変更）は認証がゼロで、127.0.0.1 限定を前提に作ってある。
  公開すれば URL を知った誰でも設定を書き換えられる
- **運用が発生する。** OSの更新、証明書、落ちたときの対応。いまは
  アイコンをダブルクリックで完結している
- **スクレイピングが通るか不明。** YouTube検索6本と Yahoo!リアルタイム7本は
  ページを読んでいるので、データセンターIPからは遮断される可能性がある。
  落ちれば動画欄とSNS実況欄が動かなくなる

Google Drive は配信層になれない。ホスティングは2016年に廃止され、直リンクは
CORS ヘッダを返さないのでWebページから読むこともできない。保管庫にはなるが、
Drive 自体は計算機ではないので収集はできない。

同一Wi-Fi内で別端末に映すだけなら `DRONERADAR_LAN=1` で足りる（7章）。
