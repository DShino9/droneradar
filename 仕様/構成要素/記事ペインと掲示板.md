[仕様書.md](../../仕様書.md) の構成要素。**記事の一覧（左右2ペイン）・電光掲示板・主要ニュースの横送り・見出しのボタン。**

| | |
|---|---|
| 受け持つ | 記事タイル・カード・ジャンル列、ジャンル送り、電光掲示板、表示切替ボタン |
| 受け持たない | 地図と動画の帯の中身（[地図の配置とキャプション](地図の配置とキャプション.md)） |

## 電光掲示板の鮮度

並び順が `importance + flagship + 媒体数×8` だけで、**時計が入っていな
かった**。点数の高い記事は窓（24時間）の間ずっと上位に居座り、掲示板は
60候補を12件ずつ3分ごとに回すので、**15分ごとに同じ見出しが戻ってくる**。
「昨日見たのがまだ回っている」はこれ。

- 点数を**6時間で半減**させる（大きい記事は半日残り、並のものは夕方には
  新着に抜かれる）
- 窓を 24時間→**12時間**（足りなければ24時間、それでも足りなければ3日）
- 候補プールを 60→**36**（浅くすると、載るのが「今日のニュースの上位」に
  なる。60件の上位ではなく）

| | 変更前 | 変更後 |
|---|---|---|
| 掲示板の記事の古さ | 10〜17時間前 | **平均4.6時間・最古11時間** |

## 記事ペイン（Yahoo!ニュース準拠）

文字を大きくしても読みにくさが残った。Yahoo!ニュースを実測して原因が
分かった——**効いていたのは文字サイズではなく幅**だった。

| | Yahoo!ニュース | 旧 | 新 |
|---|---|---|---|
| 1件の幅 | **672px** | 300px（2列） | **625px（1列）** |
| 見出し | 16px / 行間1.3 / **太さ400** | 15.5px / 1.42 / 太さ600 | **16px / 1.34 / 太さ400** |
| 行数 | 1〜2行 | 3行 | **2行** |
| サムネ | 61×61 正方形 | 46×29 (16:9) | **56×56 正方形** |
| メタ | 12px | 12.5px | 12px |

672pxなら16pxで約38字入り見出しが1行に収まる。300pxでは17字で3行に
折り返す。**太さ400**なのも意図的で、日本語は小さい字を太らせると画数が
潰れて、強調で得るより可読性で失う方が大きい。

国旗タグは見出しからメタ行へ移した。「🇺🇦 ウクライナ BlueBird Tech、…」
だと見出しの1行目が国名で埋まる。どこの話かは、誰がいつ書いたかと同じ列。

送りの間隔：ジャンル自動送り 8秒→**24秒**、主要ニュース横送り 11秒→20秒。
12本の見出しに8秒は1本0.7秒で、2行目を読んでいる間に入れ替わる。
マウスを乗せれば止まるが、**止め方を知っている必要がある**。既定値だけで
読めることが先。



## 1件でも多く入れるための削り

1列化で1ペイン12件→6件に減った分を、周りから取り返した。

| | 旧 | 新 | 効果 |
|---|---:|---:|---|
| 地図・動画の帯 | 378px | **344px**（2026-09-26 数えた） | 動画枠を幅ではなく高さで縛る（16:9のまま中央寄せ） |
| 動画の次候補 | 2件 | **1件** | |
| 記事上の「すべて」行 | 28px | **0px** | 見出しと件数はサイドバーが既に出している。切替2つは上部バーへ |
| **1列の件数** | 6件 | **7件** |

一度302pxまで詰めて8件にしたが、地図と動画が窮屈だったので1件分だけ戻した。
帯は見るためのもので読むためのものではないから、一覧の1行と引き換えにする
価値はある——4行分ではなく。 |

帯の高さの数え方：`style.css` の `.graphics { max-height: 344px }`（1200px 以下は `min(344px, 38vh)`）。
1列の件数（7件）と「302pxまで詰めた」は画面を描かないと測れないので未確認（`style.css` の覚え書きは「306px」と書いていて、どちらが正しいかも未確認）。

「絞り込み中」の表示は解除ボタンが兼ねる（例：`規制・制度 26件 ✕`）。
消すなら押す場所に書いてある方がいい。

## ジャンル送りのチップ

**カテゴリ15個ではなくグループ7個**を並べる。15個をペイン見出しに詰めると
1個20pxになり、狙って押せない。サイドバーが7グループで整理されている以上、
ここだけ第2の分類体系を持つ理由も無い。7個・30×28pxに。
（分類の定義は17（2026-09-26 数えた、`sources.py` の `CATEGORIES`）。上の「15個」がどれを数えたのかは未確認）



## 表示切替ボタンの文言

記事一覧の見出しに2つ並んでいる。この2つが**別々の流儀**で書かれていた。

| | 旧 | 問題 |
|---|---|---|
| 地図の表示 | 「グラフを隠す」→「グラフを表示」 | 動詞。押すと何が起きるかを書いていた |
| 分類の切替 | 「分類ごと」⇄「時系列」 | 名詞。いまどちらの状態かを書いていた |

隣り合うボタンで文法が違うと、どちらの読み方をすればいいのか決められない。
さらに「グラフ」という語が誤りで、この行にあるのは日本地図・世界地図・
連続再生プレーヤーであってグラフは1つも無い。**地図を消した人が地図を
探しても、「グラフを表示」に目が行かない。**

両方とも「**操作対象の名前を書き、有効なとき点灯**」に統一した。

- 「● 地図・動画」——点灯＝表示中
- 「● 分類ごと」——点灯＝ジャンル別、消灯＝新着順の一覧

文言が状態で変わらないので、消したあとも同じ場所に同じ名前が残る。
戻し方を探す必要が無い。



## 横送りは列の位置で送る

主要ニュースの横送りが `clientWidth` 分だけ動いていた。列は枠と同じ幅で
**8pxの隙間**があるので、毎回8px手前で止まり、誤差が積もって見出しが
左右に割れた状態で駐まる。列の実位置へ送るようにした。

折返しの判定も間違っていた。`max`（＝scrollLeftの最大値）は有効な位置で、
最終列はちょうどそこから始まる。それを行き過ぎと見なしていたので、
**どの回も1列目に戻り、実際には一度も送られていなかった。**

## 記事ペインの埋め方

左右2ペイン。列は上から詰めて、いっぱいになったら次の列を作る——これだと
**件数が少ないときに1列目だけに縦積みされ、右半分が丸ごと空く。**
検索で絞ると必ずこうなる。

列を埋める前に幅を埋める。必要な列数がペインの列数（2）に満たないときは、
2列に分配する（6件なら3+3、5件なら3+2）。1列しか無いときはその列を全幅に
伸ばす——半分の幅で半分が空では意味がない。

タイルは列の高さを分け合うが上限178px。上限が無いと2件のペインが
1件あたり画面の半分になり、強調ではなく不具合に見える。逆に上限が
きつすぎると、余白が列の横から列の下へ移るだけになる。
