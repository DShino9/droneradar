# DroneRadar — 地球儀（世界地図）

[仕様書.md](../../仕様書.md) の構成要素。**世界地図を球で描き、スポットライトの対象へ回して寄る。**

| | |
|---|---|
| 受け持つ | 正射投影・自転・正面回頭・ピンの時機・viewBox のズーム |
| 受け持たない | どの国を出すか（[地図のスポットライト](地図のスポットライト.md)） |
| 実体 | `droneradar/web/js/globe.js`、`maps.js` |
| 開くのはこんな時 | ピンが出ない・海の上に出る／逆回転する／ズームアウトする／寄る先がずれる |

## スポットライトのズーム

ピンの後に viewBox を対象地域に寄せる。世界地図で「ズームアウトする」
「アメリカの拡大が足りない」という挙動があり、原因は2つ別々だった。

**1. 幅を二重に数えていた。** 枠の幅を
`max(地域の幅, 地域の高さ) × 1.6 × アスペクト比` で出していた。
大きい方の辺を採ったうえで、さらに横長のアスペクト比（世界地図は 2.46）を
掛けている。横長の国では幅を2回数えることになる。

| | 旧 | 新 |
|---|---:|---:|
| 🇷🇺 ロシア | **0.51倍**（＝ズームアウト） | 1.55倍 |
| 🇨🇦 カナダ | **0.96倍** | 1.55倍 |
| 🇺🇸 アメリカ | **1.17倍** | **1.65倍** |
| 🇨🇳 中国 | 1.24倍 | 2.16倍 |
| ズームアウトする国 | 171中2 | **0** |

正しくは「地図のアスペクト比を保つ最小の枠」＝
`max(幅×余白, 高さ×余白×アスペクト比)`。倍率は 1.55〜3.5 に収める
（下限が無いと巨大な国で枠が地図を超え、上限が無いと小国が海岸線で埋まる）。

**2. bbox の中心が国の中心ではない。** 国の bbox はその国の領土すべてを
含む——アメリカならアラスカとハワイ、フランスならギアナとレユニオン、
ロシアなら日付変更線の向こう側。

| 国 | bbox の中心 | バブルのアンカー |
|---|---|---|
| 🇺🇸 アメリカ | (98, 77) ＝太平洋上 | **(128, 107)** |
| 🇫🇷 フランス | (329, 142) ＝本土より南 | 本土は約 (300, 105) |

地図が既にバブルを置くのに使っている座標に寄せる。探す人が見る場所は
そこだから。

## 世界地図は地球儀

平面の世界地図は 900×366、収める枠はほぼ正方形。どう嵌めても何かが余る
——地図を小さくして枠を空けるか、枠を低くして下の記事から場所を奪うか。
**球は正方形**なので、同じデータが同じ枠で数倍大きくなる。

常に半分は裏側にある。その代償は、効く場面で払い戻される：
**スポットライトの対象国を正面に回してからピンを打つ**ので、見せられて
いる場所が裏にあることは無い。

| | |
|---|---|
| 元データ | 正距円筒（`x=(経度+132)×3`, `y=(74−緯度)×3`）→ 経緯度に完全に逆変換できる |
| 投影 | 正射（遠方から見た球）。傾き22°N——赤道正面だと両極が隠れ、ドローン報道は北半球に多い |
| 点数 | 4,665点。各点を単位ベクトルで持つので、1フレームは1点あたり6回の乗算のみ（三角関数は回転そのものの2回だけ） |
| 描き直し | 0.35°以上回ったときだけ。171本の `<path>` は使い回し、`d` を書き換える |
| 自転 | **22秒で1周**（回っている間）。ピン表示中は止まり、世界地図の順番は14秒ごとに来るので**動いているのは半分の時間**——実質は44秒で1周、16°/秒、見えている面を横切るのに11秒 |
| 回る向き | **東向き＝画面上は左から右**。`project` は +x を画面右に送り、`toVector` は東経を +x に置くので、地図と同じく東が右。地球は東へ回るので、見えている面は右へ動く——それを起こすのは角度を**減らす**方 |
| 裏側 | 点ごとに切る。水平線をまたぐ形は、そこで線を切って手前だけ描く |
| タブ非表示時 | 止める |

**ピンの動き**：対象国を正面へ**早回しし、到着を待って**ピン → その点を
中心に球を1.55倍へ寄る → **記事が出ている間は静止** → 解放。

**回頭は必ず東回り。** 近い方の弧を取ると、少し後ろにある国へ向かうときに
一瞬逆回転する。逆回転する球は球ではなくダイヤルなので、自転と同じ向きに
統一した。10度「後ろ」の国へはほぼ1周かけて行く——それが素直な行き方で、
2秒弱で着く。

速度はイージングではなく**所要時間で決める**。イージングだと距離が速度に
なるので、近い国は弾かれるように動き、遠い国は最後がのろい。距離に応じて
0.5〜2.0秒に割り当てれば、どの距離でも同じ仕草に見える。

**リング・中心・アイコンは画面座標に1回置くだけで、球と一緒には動かない。**
だから、それらが出ている間は球を止める必要がある。ここで3つ間違えた。

1. **到着を固定待ち時間で決めていた。** 0.6秒固定で撃って「正面にあるか」を
   判定していたが、遠い国は間に合わず判定に落ち、**ピンが出ないまま**だった
   → 到着を監視する
2. **「正面に来たか」で撃っていた。** 水平線を越えた瞬間に成立するので、
   回頭の大半を残したまま撃っており、ピンは60度先の海の上に取り残された
   → 到着そのもの（`target` が消えたこと）を待つ。さらに**撃つ瞬間に
   残りの回頭を確定させる**ので、タブの間引きで数度残っても位置は正確
3. **止める仕掛けが無かった。** `target` は到着した瞬間に自分で null に
   なり、次のフレームから自転が再開する。`releaseGlobe` は既に null の
   ものを null にするだけで、何も止めていなかった
   → `spinning` フラグで止める。解放はピンを消すのと**同じtick**で
   （数百ミリ秒の隙間でも数度ぶん滑る）

拡大の中心は**箱に対する割合**で指定する。viewBox 単位（0〜400）の数値を
px として渡していたので、中心が別の場所になっていた。

**ピンはバブルとは別レイヤに置く。** バブルは球と一緒に動くので毎フレーム
作り直すが、その際 `innerHTML = ""` で層ごと消える。同じ層に置いたピンは
16ミリ秒で消えていた。

**キャプションの位置は viewBox から出す。** 元データは 900×366 だが描かれる
球は正方形。ファイルの縦横比で計算すると、平面地図の下端があった場所——
だいたい赤道——にキャプションが来て、球の下半分を覆った。

`facingRotation` は当初符号を逆にしていて、角度を打ち消すはずが倍にして
いた。日本の奥行きが0.25（本来0.97）、10か国中8か国が裏側に回っていた。
