[仕様書.md](../../仕様書.md) の構成要素。**何を「新着」として鳴らし光らせるか、「今日は何が違うか」の急上昇、収集状況の出し方。**

| | |
|---|---|
| 受け持つ | 新着の表現（6か所）・新着に数えないもの・急上昇の語の切り方と数え方・不調件数 |
| 実体 | `droneradar/web/js/rising.js`、`sidebar.js`、`sound.js`、`main.js` |
| 開くのはこんな時 | 音が鳴るのに何も光らない／急上昇に変な語が出る |

## 8.5 新着の表し方

新着は複数の場所で同時に示す。1か所だと見落とすため。

| 場所 | 表現 |
|---|---|
| 更新ボタン | じわーっと点滅 |
| サイドバー | 該当グループ行が明滅 |
| 記事カード・タイル | 枠が明滅 |
| **地図** | **記事が届いた地域が明滅** |
| レーダー | 輝点が脈打ち、外向きに広がるリングを伴う |
| カレンダー | 該当日のマーカーが明滅 |

**色はそのジャンルの色。** 単一の赤は「何か来た」しか言わない。ダッシュ
ボードが既にそのジャンルに使っている色なら「何が来たか」まで言える。
同じ記事が光らせるサイドバー行・タイル・地図・輝点が同じ色で脈打つので、
どこを見ても同じ出来事だと分かる（要素ごとに `--fresh` を設定）。

**地図には新着の表現が無かった。** 更新ボタン、サイドバー、タイル、
レーダーは光るのに地図だけ黙っていたので、地図が取りこぼしたように見えた。

## 何を新着とするか

届いたもの全部が「到着」ではない。**GitHub・動画・コミュニティは除外**する。

- GitHub は一日中リポジトリを push する
- SNS は20秒ごとに入れ替わる
- 動画はプレイヤーが延々と消化していくもので、1本増えるのは事件ではない

これらを新着に数えると、**読者がニュースと呼ばないものに対して音が鳴り**、
しかも光らせる先が記事ペインに出ない種類の項目なので「音はするのに
何も光らない」状態になっていた。

レーダーのリングは、盤上で唯一「外へ動くもの」なので、48個の輝点の中から
探さなくても目に入る。点が少し大きく少し赤いだけでは、探している時にしか
気づけない。

## 8.6 急上昇（サイドバー下段）

他のパネルは全部「何があるか」を答えている。ジャンル別の件数、地域別、
新着順。「今日は何が違うか」を答えるものが無かった。普段1日2件の話題が
今朝11件来ている——3000件の中の11件は、既存のどのランキングにも出ない。

直近24時間の出現数を、その前6日間の1日あたり平均と比べ、比率で並べる。

- 抽出は3種類だけ：ラテン語（DJI, Skydio, BVLOS）、カタカナ3字以上、
  漢字2〜6字。ひらがなは文法であって主題ではないので取らない
- 1記事につき1回。同じ記事内での連呼で上がらない
- 2字の漢語は一般語が多いので、比率のしきいを 1.6 → 3 に上げる
- **同じ記事群から出た語はまとめる。** 「アマゾン、軽量荷物の配送を都市部へ
  拡大予定」は アマゾン／軽量荷物／都市／拡大予定 が同時に跳ねる。記事集合の
  重なりが6割を超えたら、比率の高い方だけ残す
- 表示件数は枠の高さから決める。`overflow: hidden` に7行を流し込むと、
  「上昇率の高い順」の下2行が黙って消える
- **GitHub と動画は数えない。** 一日中 push され、動画検索は延々と補充
  されるので、「上昇」を測る仕掛けはそれを上昇と読む。新着の鐘から外すのと
  同じ理由。加えて GitHub のタイトルは `owner/repo — 説明` なので、
  **識別子の部分を落としてから**語を切る——ある1アカウントが54個の
  リポジトリを登録していて、`api-evangelist` がその日最大の話題として
  上がっていた
- **2つ以上の別の話題に出ること。** 件数は記事単位で、1つの出来事は
  十数本の記事としてここに届く。だから1本のよく報じられた記事から
  切り出された断片が、12回出現したように見えた。媒体数では分かれない
  （Google News は同じ出来事を多媒体から集めるのが仕事）。**話題**を
  数えると分かれる。collector が重複報道をまとめて `related` を付けて
  いるので、その組の代表IDで数える
- 漢字語は「ヶ・ヵ・ノ」を含めて切る。含めないと 青木ヶ原樹海 が
  「青木」になり、地名が人名に見える

## 収集状況の扱い

ソース91本を1本1セルで並べるパネルを一度作ったが、90個のセルが
ほぼ常に「正常」と言うためにサイドバーを使っていた。不調の件数を
「ソース管理」の行に出すだけにして、枠は急上昇に譲った。

止まったフィードは「その週ニュースが無かったフィード」と見分けがつかない
ので、件数自体は出す価値がある。「87/91」ではなく「7件不調」と書くのは、
引き算をさせないため。
