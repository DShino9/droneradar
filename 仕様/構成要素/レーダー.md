# DroneRadar — レーダー

[仕様書.md](../../仕様書.md) の構成要素。**ライブレーダーの盤面：何を載せ、何に名前を書き、どう触れるか。**

| | |
|---|---|
| 受け持つ | 輝点の定員と配分、ラベルの選び方と切り方、当たり判定、ツールチップ |
| 実体 | `droneradar/web/js/radar.js` |
| 開くのはこんな時 | 盤面が英語やSNSばかり／ラベルがはみ出す／輝点に触れない |

## レーダーの見出しが英語になる

リポジトリ名を**ラベルから完全に除外**した。順位を下げるだけでは足りず、
GitHub からの取得が多い時間帯には結局それしか記事が無く、盤面が
`trackdraw` `the big dro…` `Dragonfly G…` になっていた。

プロジェクト名を名乗るだけでドローンについて何も言っていないうえ、
**翻訳器が唯一手を付けない種類のタイトル**でもある。日本語をいくら
集めても盤面が英語だったのはこれが理由。輝点としては残り、
ツールチップも持つ。



## レーダーの接点に触れる

輝点は直径2.6単位——画面上で約3px——のうえ脈動しているので、当てるのが
運任せだった。**当たり判定を別に置く。** 透明で面積5倍、脈動しない円を
輝点の上に重ね、そちらがポインタを受ける。

ツールチップも自前に置き換えた。ブラウザ標準の SVG `<title>` は表示まで
約1秒、1行、ポインタが1px動くと消える。48個の3px の接点に対しては
無いのと同じ。自前のものは即座に出て、種別・発信元・経過時間・見出し全文を
出す。SNS本文からURLを外し、4行で打ち切る（それ以上は指している盤面を
覆ってしまう）。

クリックで記事を開くのは以前から動いていたが、当たり判定が小さすぎて
届いていなかった。



## レーダーに何を載せるか

盤面の定員は48。年齢順に詰めると**SNSが全枠を取る**。投稿は分単位で届き、
記事は書かれた時点で数時間前だから。ドローン**ニュース**の盤面が
ツイート48件でニュース0件になっていた。

そこで記事とSNSを別々に順位付けし、記事に55%を確保。余った枠は相手に回す。

ラベル（名前を書く5件）の選び方：

1. 記事が先、SNSは後
2. 記事の中では**新着順ではなく重要度順**。新しいことは中心に近いことで
   既に示している。ラベルが足すべきなのは「どれが効いているか」
3. **見出しが識別子のものは下げる。** collector は GitHub を一律12点と
   採点するが、これは大半のニュースより高い。点数は間違っていない
   （リリースは重要）——「タイトルが文かどうか」を測っていないだけ。
   `Yarindos/drone_in_sky` は名前であって、名前は @ハンドルと同じくらい
   何も言わない。輝点としては残り、ツールチップも持つ
4. SNSは本文から@メンション連鎖・URL・ハッシュタグ・絵文字を落とした
   残りを使う。アカウント名では「8人が投稿した」以上のことを言わない

## レーダーの文字

ジャンル名は円の外に置く。内側にあった頃は自分のセクターの輝点と、
毎分4回通るサーチビームの上に重なっていた。

外に出すために viewBox を 200×200 から 268×200 に広げている。パネルは
円より横に広く、正方形の viewBox では左右に36pxずつ余っていた。高さは
変えていないので、円の直径は 239px→229px とほとんど縮んでいない。

ジャンル名は「・」で切って前半だけを出す（防衛・軍事→防衛、開発・OSS→
開発）。文字数で切ると「開発・O」「ビジネス・」になり、描画の失敗に見える。

記事の見出しは句読点で切る。ただし**予算の6割以上を使う位置に限る**。
最初の句点で切ると「Amazon、ドローン配送を強化、注文数100万件を目指す」が
「Amazon」になる——正しい節ではあるが、ニュースではない。

ラベルの幅は全角・半角を数えて見積もる。1文字5.6と一律に置いていたため、
8文字のつもりが20文字通って盤面からはみ出していた。
